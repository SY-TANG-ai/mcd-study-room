## 这是什么

利用 WorkBuddy 的"项目"功能，把"项目"变成一个"共享自习室"。

几个有共同备考目标的好友一起建一个项目，每天记录打卡、共享资料。Agent 帮你解读资料、帮你答疑解惑、提醒你关键时间节点，用麦当劳的热情给你打气，记录每天的完成情况和过程中的趣事。

到了预先设定的天数节点，每个人都坚持打卡了，就奖励一顿麦当劳聚餐。

聚餐那天会再建一个「讨论聚餐」的任务。大家七嘴八舌地说时间和想吃什么，Agent 负责规划、算账、下单。

**它是两个 Agent Skill，不是打卡 App，也不是点单机器人。**

| | `study-planner` | `maimai-butler` |
|---|---|---|
| 管谁 | 一个人 | 整间自习室 |
| 管什么 | 这个人今天学什么 | 这群人有没有在走、什么时候该吃一顿 |
| 说话对象 | 一对一 | 全组，发**项目动态** |
| 要 MCP 吗 | **不要**，纯文件读写 | 要（只在聚餐和考前那两处） |

一间自习室要两个都在：左边排每天的活，右边记账、催人、安排那顿饭。**少了右边，这间屋子就只剩一张计划表，没人记得住你昨天说了什么。**

## 一间屋子跑到最后，会剩下什么

> 仓库里的 `templates/` 给了一份跑完全程的完整样例。**数字是编排的，格式是真的**——真跑起来你会得到自己的那一份。

| | |
|---|---|
| 打卡 | **19 天**，最长连续 11 天（10-30 → 11-09） |
| 人次 | 共 **57 人次**：完成 41、算完成 9、请假 5、未完成 2 |
| 全勤阶段 | 2 个，换来了 **2 顿麦麦** |
| 吃掉的 | 一起吃了 2 次，**214.5 元** |
| 最后 | 一份结业回忆录：谁稳、谁后劲足、哪天谁差点放弃 |

那份回忆录里有一句是这样写的：

> 10-28，第 7 题：小A 卡在夹逼那道题上四十分钟，中途说「我是不是不适合学数学」。第二天自己把那题做出来了，还说了一句「原来就是没想到拿 1/n 当上界」。

这句话不是 Agent 编的——来自那天晚上小A 自己写在 `记录.md` 里的。

## 安装

### 第 0 步 · 准备

- 装好 [WorkBuddy](https://www.workbuddy.cn)
- Python 3.8 以上（只有语气抽样脚本用，纯标准库，不用装任何包）
- 一间屋子 2～5 个人。**体验版单项目上限 3 人**

### 第 1 步 · 装 Skill

一个仓库里有两个 skill，**要分别复制两个目录**（一次只能装一个）。

```bash
git clone https://github.com/SY-TANG-ai/mcd-study-room.git

# 用户级：所有项目都能用
cp -r mcd-study-room/skills/study-planner   ~/.workbuddy/skills/
cp -r mcd-study-room/skills/maimai-butler   ~/.workbuddy/skills/
```

Windows 用户没有 `cp`，把 `skills/` 下那两个目录直接复制到 `%USERPROFILE%\.workbuddy\skills\` 即可。

**装完确认一下**：每个目录里都有一个 `SKILL.md`。Agent 靠这个文件认识它。

### 第 2 步 · 开一间自习室

在 WorkBuddy 里新建一个**项目**，把要一起备考的几个人拉进来。

然后在这个项目里说一句：

> 建个自习室，一起备考

它会问你几件事：考什么、什么时候考、每天大概能挤出几小时、手上有什么资料。答完，`{资产}/自习室/` 就建起来了。

**每人各自排自己的计划**——这是有意的，各人的考试和作息都不一样。

### 第 3 步 · 接麦当劳 MCP（可选）

不接，打卡、计划、回忆录全部照常跑，只是「打卡达标就吃一顿麦麦」这句要你自己吃完回来记一笔。

接了，它能查门店、配券、算钱、生成订单，考前还能按营养数据给你挑一份早餐。

1. **申请 Token**：<https://open.mcd.cn/mcp> → 手机号登录 → 右上角控制台 → 激活
2. **写配置**：填进 `~/.workbuddy/mcp.json`（照抄 `mcp-config.example.json` 的结构）
3. **重启会话**，让它生效

> 仓库里的 `mcp-config.example.json` 只有 `${MCD_MCP_TOKEN}` 占位符，**没有任何真实凭据**。你的 Token 不要提交到任何地方。

**建项目的那个人配一次就行**，其他人不用各配一遍。

### 第 4 步 · 验证装好了

新开一个会话，说一句：

> 今天学什么

如果它**先问你还剩多少时间、昨天学到哪了**，然后给出具体到"做哪几题、看哪几页"的安排——那就是好了。

如果它**直接甩给你一份通用学习计划表**（"第 1 天：复习基础概念"）——那是没加载上。检查 `SKILL.md` 位置，重开会话。

## 用起来是这样

### 第 0 天 · 每人排一张计划表

计划表**只把第一个阶段排到天**，后面只写"干什么、什么范围、用哪些资料"。

这不是偷懒。提前三十天把每一天都用日期定死，写出来的都是假的——你不知道第三周会在哪里卡住。所以后面边走边改，`整体计划.md` 一改，第二天立刻生效。

### 每天 · 学，然后收个尾

晚上它会问你今天怎么样。你说完，它做两件事：

- 写一份 `记录.md`——有情绪、有原话，给人看
- 写一份 `今日学习情况.md`——字段固定、只填事实，给管家看

**分开是有原因的。** 打卡算不算完成，不能从你自己的感受里推——那是你说的，不算数。

### 该吃麦麦了

两两相邻的聚餐日之间算一个阶段。这个阶段里每个人都按计划完成了，就吃。

它会发一条动态宣布"这顿成了"，然后跟大家聊：想吃什么、在哪、什么时候。接着查门店、看菜单、配券、算钱、生成订单给你扫码付。

### 考完那天

最后一场考试结束，它写一份结业回忆录：这一路上的数字、几个有画面的故事、你们每个人的特点。

写完之后，这间屋子就散了。档案留在项目资产里，想翻还能翻到。

考前那天早上，它会 @ 当天要考试的那个人，顺带建议一份麦满分——理由是算出来的：碳水热占比低、蛋白够，撑得到中午。用的是麦当劳公开的营养数据。

## 数据都在哪

全部在项目的**资产**里，云端共享，几个人都能看。

```
{资产}/自习室/
├── 打卡.md              ← 管家写：每人每天一行，整间屋子的账本
├── 麦记.md              ← 管家写：每次吃麦当劳的记录
└── {成员名}/
    └── day-01-20261026/
        ├── 计划.md          ← 今天学什么
        ├── 记录.md          ← 有情绪有原话，给人看
        └── 今日学习情况.md   ← 字段固定，给管家看
```

> 真跑起来的这些文件**只存在你的项目和本地**，`自习室/` 已被 `.gitignore` 排除，不会进仓库。

**一个限制必须说清**：定时任务是**个人级**的，只有建它的人能看到和修改，也只在那个人的设备上跑。所以几条规则全由建项目的人建，**他的电脑关机，它们就不跑**。这不是缺陷，是当前的机制——所以别让全组以为这是项目的公共能力。

## 它的语气从哪来

管家的说话方式是从麦当劳官方微博继承的。

- `corpus/weibo-corpus.jsonl` 收录 **586 条**官微公开博文，时间跨度 2025-11 至 2026-10
- 抓取后做了清洗：去掉转发、置顶、纯图，去掉含价格符号和具体日期时间的条目
- **只学说话方式，不搬原句**

`weibo-sample.jsonl` 是从中按月加权抽样的 60 条，由脚本生成、不进仓库：

```bash
python skills/maimai-butler/scripts/sample_corpus.py            # 默认 120 条
python skills/maimai-butler/scripts/sample_corpus.py --n 60     # 只抽 60 条
python skills/maimai-butler/scripts/sample_corpus.py --seed 7   # 复现某一次抽样
```
